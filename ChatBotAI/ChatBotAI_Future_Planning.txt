                    PRIORITY 2 - HIGH VALUE FEATURES

[X] 6. QUICK REPLY TEMPLATES (CANNED RESPONSES) (Batch 3 - 2026-02-23)
    ............................................
    Category: Feature (Major)
    Effort: Medium (3-4 hours)
    Description:
      Hosts repeatedly send the same information: WiFi passwords, check-in
      instructions, house rules, directions, parking info. A template system
      would save massive time every day.

    Implementation:
      - New database table: reply_templates (id, name, content, category)
      - Settings page: CRUD interface to manage templates
      - Conversation view: dropdown button next to message input
      - Template variables: {guest_name}, {property_name}, {check_in_time}
      - Variables auto-replaced when template is inserted into textarea
      - Host can edit before sending (not auto-sent)

    Example templates:
      - "WiFi Info" -> "WiFi Name: ApartmentXY, Password: ..."
      - "Check-in" -> "Hi {guest_name}, check-in is at {check_in_time}..."
      - "Directions" -> "From the train station, take..."
      - "House Rules" -> "Please note the following..."


[X] 7. PROPERTY MANAGEMENT UI (Batch 3 - 2026-02-23)
    .........................
    Category: Feature
    Effort: Medium (2-3 hours)
    Description:
      The Property model is fully built but the Settings page only has a
      placeholder. Add a real CRUD form so the host can manage properties:
      name, address, description, amenities, WiFi password, check-in/out
      times, house rules, pet policy, max guests, bedrooms.

      This directly improves AI response quality because property info is
      already injected into AI prompts - it just needs real data.

    Implementation:
      - Settings page: expandable property cards with edit/delete
      - Add Property modal with all fields
      - Amenities as tag input (type and press Enter to add)
      - Link conversations to specific properties
      - API: POST/PUT/DELETE /api/properties


[X] 8. DASHBOARD STATISTICS CARD (Batch 3 - 2026-02-23)
    ............................
    Category: Feature / UI
    Effort: Medium (2-3 hours)
    Description:
      Add a stats summary bar at the top of the inbox page:
      - Total conversations (all time / this month)
      - Unread count (prominent badge)
      - Messages today / this week
      - Average response time
      - Active guests count
      - Optional: small sparkline chart for message volume

    Implementation:
      - New API endpoint: GET /api/stats
      - Stats card component above the filter bar
      - Compact, non-intrusive design (collapsible)
      - Updated on each polling cycle


[X] 9. AI TYPING INDICATOR (Batch 2 - 2026-02-23)
    ......................
    Category: UX
    Effort: Small-Medium (1 hour)
    Description:
      When AI is generating a response (15-30 seconds), show a pulsing
      "..." bubble in the message area (like WhatsApp/iMessage typing
      indicator) instead of only disabling the button. Makes the wait
      feel much shorter and more natural.

    Implementation:
      - Insert a temporary "typing" message div when AI request starts
      - CSS animation: three dots pulsing in sequence
      - Remove and replace with actual AI message when response arrives
      - Show "AI is thinking..." label

[X] 13. GUEST AVATAR COLORS (Batch 2 - 2026-02-23)
     .....................
     Category: UI Polish
     Effort: Small (30 min)
     Description:
       Assign each guest a consistent avatar color based on a hash of their
       name. Pick from a palette of 8-10 distinct colors. Makes scanning
       the inbox much faster as you can identify guests by color.

     Implementation:
       - Hash function: simple string hash -> color index
       - Palette: blue, green, orange, purple, teal, pink, red, indigo
       - Apply to conversation-avatar in inbox and guest-avatar in header


[ ] 14. AUTO-SAVE DRAFT MESSAGES
     ..........................
     Category: UX
     Effort: Small (45 min)
     Description:
       If the host starts typing a reply and navigates away (back to inbox,
       closes tab, etc.), save the draft text to localStorage keyed by
       conversation ID. Restore it when they return to that conversation.

     Implementation:
       - Save on input event (debounced)
       - Restore on page load
       - Clear on successful send
       - Key format: chatbot_draft_{conversationId}


[ ] 15. GUEST MERGE TOOL
     ...................
     Category: Feature
     Effort: Medium (3 hours)
     Description:
       When the same person contacts via email and then WhatsApp, two guest
       profiles may be created. A merge tool would:
       - Show "Merge with another guest" button on guest profile
       - Search/select the duplicate guest
       - Combine all details, conversations, and platform IDs
       - Delete the duplicate record

     Implementation:
       - API: POST /api/guests/<id>/merge with target_guest_id
       - Move all conversations and details to the primary guest
       - Copy over any platform IDs the primary is missing
       - Confirmation dialog showing what will be merged


[ ] 16. EXPORT CONVERSATIONS
     ......................
     Category: Feature
     Effort: Medium (2 hours)
     Description:
       Allow exporting a conversation or guest profile as PDF or plain text.
       Useful for record-keeping, sharing with co-hosts, or printing.

     Implementation:
       - "Export" button on conversation and guest profile pages
       - Formats: Plain text (.txt), CSV, or PDF
       - Include guest info, all messages with timestamps, memory items
       - API: GET /api/conversations/<id>/export?format=txt

                    CODE QUALITY & TECHNICAL DEBT

[ ] A. REPLACE INLINE SCRIPTS WITH EXTERNAL JS FILES
     ................................................
     The conversation.html and guest_profile.html templates have large
     inline <script> blocks. Extract these into dedicated JS files:
       - static/js/conversation.js
       - static/js/guest-profile.js
     Benefits: caching, cleaner templates, easier maintenance.


[ ] B. API ERROR RESPONSE STANDARDIZATION
     ....................................
     Standardize all API error responses to a consistent format:
       { "error": "message", "code": "ERROR_CODE" }
     Makes frontend error handling more predictable.


[ ] C. INPUT VALIDATION MIDDLEWARE
     ............................
     Add a reusable validation layer for API endpoints instead of
     repeating validation logic in each route handler.


[ ] D. AUTOMATED TESTS
     ..................
     Add pytest tests for:
       - API endpoints (status codes, response format)
       - Memory extraction (given input X, expect output Y)
       - Guest identification logic (cross-platform matching)
       - Filter and search functionality


[ ] E. RATE LIMITING ON AI ENDPOINTS
     ...............................
     Add rate limiting to AI generation endpoints to prevent accidental
     spam-clicking from queuing multiple expensive Ollama requests.
